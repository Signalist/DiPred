# 修正组件与方向诊断

在仓库根目录执行：

```bash
export PYTHONPATH="$PWD/../Forecast/Runtime/.deps${PYTHONPATH:+:$PYTHONPATH}"
TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=0 CUBLAS_WORKSPACE_CONFIG=:4096:8 PYTHONDONTWRITEBYTECODE=1 \
  python -m research.correction_component_diagnostic.run --output /absolute/path/to/new-results
```

本地依赖原实验锁定的条件缓存、开发预测缓存、250 步权重和原生权重。只写指定空目录，出现资源或强制核验失败时保留已生成文件及 STOP/COST。仅合成检查使用同一入口的 `--synthetic-only`。已有缓存的离线评分和分解可用 `--cached-only`，该入口不新增采样前向。实际诊断禁止优化器与参数更新、XPF 或反馈重建、500 步模型推理、测试和 extension 评分。运行前显式关闭 matmul/cuDNN TF32，使用原环境的确定性 cuDNN 与 FP32 权重、状态及噪声；原评分使用 FP64 归约。

## 固定清单

所有窗口均为 start420，历史及上一预测的目标为 [420,440)，当前目标为 [440,460)。开发取原 12 条。训练以原有合法缓存目录索引为准，Re 数值升序逐组轮取文件名字典序首条尚未抽取者，满 6 条停止。开发阶段取每组字典序前两条。清单锁定后才读取评分或检查目标张量。训练 6 条只给训练侧线索。噪声从原完整 split 批形状及顺序按成员 seed 重构后取对应轨迹，逐成员核对 SHA-256。评分使用轨迹等权，保留帮益及损害的轨迹、Re 和 u/v 结果。

## 预计执行量

|顺序|项目|新增完整 32 成员四步组|
|---|---|---:|
|1|合成评分、梯度、汇总及保存，锁定身份|0|
|2|开发缓存离线均值与中心化成员场分解|0|
|3|开发 N、C0 J、C1 J 缓存复现各一组，同一 C1 J 未来污染再一组|4|
|4|18 窗各 arm 的 O/G 与训练 6 窗的 N/J|90|
|5|C1 全阶段 0.5，覆盖固定 18 窗|18|
|6|6 开发窗在 O/J 端点各一张完整采样图|12|
|7|各 Re 首条整体、以及首 Re 首条最早与最晚阶段，双边差分|40|

|合计|其中带梯度图 12 组，终点评分反向请求 24 次|176|

硬上限为 192 组完整前向、12 组带梯度图、24 次真实 `autograd.grad`。原生 N 每窗在两 arm 之间共享。开发余下的 N/J 用完整已生成缓存。复现检查使用相同 32 成员批形状，要求张量完全相等；梯度图端点也须复现已经评分的 O/J。原数据有限差分以 h=0.01 和 0.005 分别在两个端点做中心差分，对经验与 Fair 各自比较。两尺度导数与自动求导均须同号，符号绝对值须高于 1e-9，三对差值均须在 1e-7 + 0.02×max(|a|,|b|) 内，否则标记不确定/非光滑。报告给出每个完整扰动的预测哈希、原始分数与导数。超出部署区间的微小扰动仅用于两侧差分。

组件 N/O/G/J 分别对应原生、仅训练 out、仅训练 G、共同启用。G 存在时在每一步以实际状态和 up2 特征重算。四个去噪标签依采样顺序为 99/66/33/0。阶段梯度仅对诊断用 lambda。E_off 仅归零 E；W_off 同时归零 W、W_mean。核心对照使用 C0 的零条件或 C1 的实条件；两 arm 的原始缓存身份相同，N/O 忽略条件。

P_mean 与 P_shape 在 FP64 对缓存固定输出做代数分解，成员不重排。验证中心化成员场及所有成员对的逐点差、P_shape 均值与两种尺度的均值 MSE。经验/Fair 差与经验半距离项除以 31 核对。分解和组件均显式记录交互。评分变化定义为前项减参照，分数为负表示降低，宽度和方差的符号描述变化方向。
