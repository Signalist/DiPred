# 当前可靠性结果与完整分析数据

`per_case.csv`包含10种预先明确版本、每种1872条记录，共18,720条。每条是一个集合/轨迹/窗口/u或v通道，保留全部已评估窗口，无按改善幅度筛选。

`start`为历史起点：输入[start,start+20)，目标[start+20,start+40)。原始时间段`main`目标到600，`confirmation`为后续到800，仅为历史额外时间段，名称不代表独立确认。新比较统一使用`warm`：起点20…760、38个窗口，排除首个冷启动窗口；`summary.json`保留原两段及warm/cold分层。

Score和width按各通道训练标准差标准化，为无量纲；MSE是原数据速度数值的平方单位，不是比值，元数据不足以确认其为m²/s²。所有方法点预测相同，本次工作改进可靠性输出，不改变点MSE。

## 可重算项目

仓库根目录运行`python analyze_reliability.py`，仅需Python标准库，不需要GPU、原始数据或权重：

- 核对18,720条窗口数据的14,880个分组数值与原汇总一致。
- 用既定8指标、6个开发/测试Re、u/v共96项、1e-6容差重算改善/持平/退步。
- 输出`current_regression_counts.json`、`current_counterexamples.csv`和`analysis_verification.json`。
- 对照包括早期2D、原rich、匹配对称尾、当前低反例主线及去噪提示强参考。

低反例版本相对早期2D仍4/96项退步：开发6300-v、7575-u/v的覆盖偏差，测试13950-u的区间宽度；相对匹配对称尾仍46/96项退步。全部保留，不能以“只剩4项”替代强参考比较。

三个实验子目录保留完整原始协议、头权重哈希、审计和反例表；其中也包含未部署的对照，并不表示本包提供它们全部推理权重。`portable_inference_audit.json`核验独立导出的两个可部署预设，`provenance.json`保留结果源文件哈希。

原8指标为Score、width、全窗top10%误差能量捕获、逐帧top10%捕获、相对AURC、最差帧覆盖、最差8×8区域覆盖、|coverage−0.9|。排序风险是实际已发区间半宽。最差区域覆盖按每个窗口在固定8×8空间区域取时空平均后取最小，再作轨迹/工况平均，不是任意位置的联合覆盖保证。

所有评估轨迹都有历史研究使用记录；最终区间校准与风险头拟合数据隔离，仍没有新鲜独立确认、严格条件覆盖或整段联合覆盖保证。窗口、区域、像素有相关性，逐窗口胜率和96项计数仅作描述。
